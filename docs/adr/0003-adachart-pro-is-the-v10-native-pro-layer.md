# `AdaChartPro` is the v10-native Pro layer

> **Status — the repo split.** This ADR is what made `AdaChartPro` the only Pro
> layer in development, and that is still true. What changed is where the other
> two went: `TChartPro` was **moved to the `tcharts` repo** (it lives there
> now, still frozen, still built and exported), and `KChartPro` — the frozen v9
> wrapper — was **removed** rather than moved. This repo now publishes
> `AdaChart` and `AdaChartPro` and nothing else. The measurements and the
> reasoning below are kept as they were recorded: they are the evidence the
> decision rests on, and the numbers still describe the engines they describe.

`TChartPro` and `KChartPro` reach the same feature set on two different engines, and `docs/perf/chart-pro-comparison.md` measured what that costs. With 30,000 candles and six indicators, `KChartPro` reached first paint in ~37 ms and retained ~15.7 MB, where `TChartPro` needed ~387 ms and ~189 MB. The gap is structural, not a defect: `lightweight-charts` has no indicator concept at all, so `TChartPro` computes every study on the React side, and before the incremental fix it recomputed all of them over the whole history on each new candle. An engine that owns *Indicator* and *Pane* natively does that work incrementally for free.

So the Pro layer stops being engine-neutral. **`AdaChartPro`** (`src/components/adachart-pro/`) is built on **`AdaChart`** (`src/components/adachart/AdaChart.tsx`) — which is `klinecharts` **v10** directly. There is no second engine in the stack, and no engine-neutral Pro abstraction to keep honest. `AdaChartPro` adds only what v10 does not ship: the toolbar, the watermark, and one place to hold the values the toolbar moves.

The rename went all the way through the tree. `src/components/klinecharts/` became `src/components/adachart/`; `KChart.tsx` became `AdaChart.tsx`; `k-chart-options.ts` and `k-line-styles.ts` became `adachart-options.ts` and `adachart-styles.ts`; the identifiers followed (`KChartProps` → `AdaChartProps`, `KCHART_DEFAULTS` → `ADACHART_DEFAULTS`), and the prose in every comment and story went with them. The `./k-chart` entry point becomes `./adachart`, and the Pro layer's is `./adachart-pro`. No deprecated alias is published: nothing downstream imported `./k-chart` when this was decided, so an alias would have been a permanent public surface bought for zero callers. `KChartPro` keeps its name and its `src/components/klinecharts-pro/` directory — it is the frozen v9 wrapper, and renaming it would collide with the v10-native `AdaChartPro`.

`TChartPro` and `KChartPro` were **frozen**: still built, still exported, still documented, but receiving no new features. Freezing rather than deleting kept downstream imports working and kept the comparison in the perf docs reproducible. The split has since settled what "keeping them" meant for each: `TChartPro` moved to the `tcharts` repo, where it is still built and exported and still frozen; `KChartPro` was removed outright, because it was the one wrapper that pinned the v9 runtime into this repo's bundle and nothing else in it was still wanted.

## Consequences

- **`lightweight-charts` is no longer a Pro engine, and no longer a dependency of this repo.** `TChart` was a first-class wrapper on it (ADR-0001 is untouched — wrappers still do not hide their engine), but nothing new was built on it, and its Pro layer existed to be compared against rather than extended. Both `TChart` and `TChartPro` now live in the `tcharts` repo, so this repo neither depends on `lightweight-charts` nor ships any part of it.
- **`AdaChartPro` is bounded by `AdaChart`'s incremental path.** Its cost per live candle is the wrapper's cost plus the toolbar's state, so the wrapper's `structuralKey`-driven rebuild rules are now a performance contract rather than an implementation detail. That makes the whitelist inside `structuralKey` load-bearing: it has to carry every field that changes the *shape* of the set, which is why `stack` — the field `AdaChartIndicator` adds to put a main-pane indicator on the price pane — belongs in it. Non-structural fields such as `visible` and `styles` stay out on purpose. An overlay's `points` is *in*: a different anchor is a different drawing, so a declarative tool is rebuilt when its geometry changes — which is also why the live stories anchor their tools to fetched history rather than the moving series, so a push does not count as a geometry change. `lock`, `mode` and `visible` stay out, since the engine and the user own them once the tool exists. Note what `stack` has to *do*: not `isStack`, but an explicit `paneId` (`CANDLE_PANE_ID`). In v10 `createIndicator` assigns `paneId ??= createId("indicator_pane_")`, so an indicator given no `paneId` always opens a pane of its own and `isStack` only decides whether that pane's existing indicators are cleared first — which is why `isStack` alone stacked every main-pane indicator into a pane of its own, leaving the price pane squeezed to zero height.
- **`KChartPro` was pinned to v9 and could not follow an upgrade — and was removed.** It depended on ADR-0002's redirect, so it stayed where it was while upgrading `klinecharts` only ever improved `AdaChart` and `AdaChartPro`. That was the concrete reason the freeze was safe; the split then made it moot, because with `KChartPro` gone nothing in this repo imports the v9 runtime any more.
- **The perf page carried v9 and v10 side by side**, and a bare `klinecharts` specifier no longer meant one thing. ADR-0002's `resolveId` redirect was there because the blanket alias that used to pin every `klinecharts` import to v9 cannot express the split: `@klinecharts/extension` and `AdaChartPro` both need v10. The perf harness therefore read the registries from `klinecharts-v9` and `klinecharts` separately, which is also what made the three feature counts comparable instead of accidentally identical. **Both of those are now gone**: the harness no longer exists here (the `perf/` directory and `scripts/bench-charts.mjs` were removed with the benchmark tooling, so `docs/perf/chart-pro-comparison.md` is a historical record rather than something this repo can re-run), and so does the v9 copy the redirect existed to serve — the repo ships one engine, v10, and nothing installs a second klinecharts.
- **The overlay counts are not measured the same way.** `@klinecharts/extension` registers its tools on first mount, so the harness reads `features()` after the warm-up; read at page load, `AdaChartPro`'s set reports as the 16 built-ins alone.
- **The watermark forces the chart surface off the chart layer.** The watermark is a DOM layer under `.adachart-pro__chart`, which only works while everything between them is transparent. `AdaChart` normally paints a background itself — its canvas is transparent, so the wrapper supplies the surface — and anything it paints lives *inside* the chart layer, above the watermark. So `AdaChartPro` passes `transparent` and paints the surface as `--adacp-surface` on `.adachart-pro__body` instead. The two must move together: restoring the background onto the chart layer silently hides the watermark. This originally had to be measured by hiding the watermark and comparing screenshots; it is now guarded directly by `src/components/adachart-pro/adachart-pro-layering.test.ts`, which asserts both halves of the invariant (the surface is painted on `.adachart-pro__body`, and neither the chart layer nor the chart's host element is given anything opaque).
- The 67-vs-68 drawing-tool drift noted in `README.md`'s `TChartPro` row was left in place: `TChartPro` is frozen, so the sentence was not rewritten. That row is gone from this repo's `README.md` now — `TChartPro` lives in the `tcharts` repo — but the drift itself still stands there, and this report's runtime registry is still the authority for the number.
